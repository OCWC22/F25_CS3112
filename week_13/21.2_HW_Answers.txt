SECTION 21.2: MST ALGORITHMS (KRUSKAL'S & PRIM'S)
================================================================================

--------------------------------------------------------------------------------
PART 1: (DEFINITIONS & CONCEPTS)
--------------------------------------------------------------------------------
1. **Greedy Algorithm:** An approach that makes the locally optimal choice at each step (e.g., "pick the cheapest edge right now") with the hope of finding the global optimum.
   - *Note:* For MSTs, Greedy ALWAYS works. For other problems (like Chess), it usually fails.
2. **Adjacency Matrix:** A 2D grid (V x V) where cell [i][j] stores the weight of the edge between node i and node j.
   - *Pros:* Fast to look up "Is there an edge between A and B?" (O(1)).
   - *Cons:* Uses lots of memory (V^2), slow to iterate if edges are few.
3. **Adjacency List:** A list where each node stores a list of its neighbors.
   - *Pros:* Saves memory for sparse graphs.
4. **Priority Queue (Min-Heap):** A data structure that organizes items so you can always "Extract the Minimum" in O(log N) time.
   - *Crucial for:* Prim's Algorithm and Dijkstra's Algorithm.
5. **Disjoint Set Union (DSU) / Union-Find:** A data structure that tracks which nodes are in the same group.
   - *Operations:* `Find(x)` (Which group is x in?) and `Union(x, y)` (Merge group x and group y).
   - *Crucial for:* Kruskal's Algorithm (to detect cycles).

### 21.2-1
**Problem:** Show that for each MST T, there is a way to sort edges in Kruskal's algorithm so it returns T.

**The Issue:**
Kruskal's algorithm sorts edges by weight. If two edges have the *same* weight (e.g., Edge A and Edge B both cost 5), the order is undefined. Picking A first might lead to a different tree than picking B first.

**Example with Multiple MSTs:**
```
Graph with tied edge weights:

      A
     / \
    /   \
   1     1
  /       \
 /         \
B-----------C
      1

All edges have weight 1 - there are 3 possible MSTs!
```

**Step-by-Step Solution:**

**Target MST T:** We want Kruskal to return {(A,B), (B,C)}

**Special Sorting Rule:**
1. Sort by weight (primary)
2. For equal weights: edges in T come first!

```
Sorted edges:
1. (A,B) - weight 1, IN T  ← Pick first
2. (B,C) - weight 1, IN T  ← Pick second
3. (A,C) - weight 1, NOT IN T ← Reject (forms cycle)
```

**Kruskal execution:**
```
Step 1: Add (A,B)
   A
   |
   1
   |
   B
   |
   C

A and B now connected ✓
```

```
Step 2: Add (B,C)
   A
   |
   1
   |
   B
   |
   1
   |
   C

B and C now connected ✓
```

```
Step 3: Try to add (A,C)
   A
   / \
  1   1
 /     \
B-------C

Check: A and C are already connected (A→B→C)
This would create a cycle! → REJECT ✗

Result: MST = {(A,B), (B,C)} = Exactly our target T!
```

**Conclusion:** By breaking ties in favor of edges in our desired MST, we can make Kruskal produce any specific MST.

**LeetCode Pattern:**
*   **Problem:** "Lexicographically Smallest Equivalent String" (Union-Find).
*   **Pattern:** When multiple valid answers exist, we often need a secondary sorting rule (like alphabetical order) to ensure a deterministic output.

### 21.2-2
**Problem:** Implement Prim’s algorithm in O(V^2) using an adjacency matrix.

**Why O(V^2)?**
- Usually, Prim's uses a Priority Queue (Heap) and runs in O(E log V).
- However, if the graph is **Dense** (lots of edges, E ≈ V^2), then O(E log V) becomes O(V^2 log V), which is slower than O(V^2).
- So, for dense graphs, we ditch the Heap and use a simple Array.

**Example Graph and Execution:**

**Adjacency Matrix:**
```
   A  B  C  D
A[ 0, 4, ∞, 1]
B[ 4, 0, 2, 3]
C[∞, 2, 0, 5]
D[ 1, 3, 5, 0]
```

**Graph visualization:**
```
    4
A-------B
 \     |3
  \1   |
   \   |2
    D--C
```

**Step-by-Step Algorithm:**

**Initial state:**
```
dist[] = [0, ∞, ∞, ∞]  ← A is source
visited[] = [F, F, F, F]
```

**Iteration 1: Find minimum unvisited**
```
- Scan dist: A=0 (min), B=∞, C=∞, D=∞
- Pick A (dist=0)
- Mark A visited: [T, F, F, F]

Update neighbors (scan A's row):
- dist[B] = min(∞, 0+4) = 4
- dist[C] = min(∞, 0+∞) = ∞
- dist[D] = min(∞, 0+1) = 1

Result: dist = [0, 4, ∞, 1]
```

**Iteration 2: Find minimum unvisited**
```
- Scan unvisited: B=4, C=∞, D=1
- Pick D (dist=1)
- Mark D visited: [T, F, F, T]

Update neighbors (scan D's row):
- dist[B] = min(4, 1+3) = 4 (no change)
- dist[C] = min(∞, 1+5) = 6

Result: dist = [0, 4, 6, 1]
```

**Iteration 3: Find minimum unvisited**
```
- Scan unvisited: B=4, C=6
- Pick B (dist=4)
- Mark B visited: [T, T, F, T]

Update neighbors (scan B's row):
- dist[C] = min(6, 4+2) = 6 (no change)

Result: dist = [0, 4, 6, 1]
```

**Iteration 4: Find minimum unvisited**
```
- Only C left with dist=6
- Pick C, mark visited

Final distances: [0, 4, 6, 1]
```

**Complexity Analysis:**
- Each iteration: O(V) to find minimum + O(V) to update neighbors
- V iterations total: V × O(V) = **O(V²)**

**Real Engineering Application:**
*   **Scenario:** **All-to-All Communication in HPC.**
    - In High-Performance Computing (supercomputers), every processor often connects to every other processor (Dense Graph).
    - Managing a complex Heap data structure adds overhead (pointers, memory jumps).
    - A simple array scan (O(V^2)) is extremely CPU-cache friendly and faster for these dense, hardware-level topologies.

### 21.2-6
**Problem:** Analyze a Divide-and-Conquer MST algorithm: Partition V into V1, V2, solve recursively, then add min edge crossing the cut.

**The Idea:** "Can we build an MST for the left half, an MST for the right half, and just stitch them together?"
**The Verdict:** **NO.** This is a classic algorithm design mistake.

**Counterexample Where It Fails:**

**Graph where algorithm makes poor local decisions:**
```
    A -------- C
    |100      |1
    |          |
    |100      |100
    |          |
    B -------- D
    |1        |1
    |          |
    +----------+

Partition: Left = {A, B}, Right = {C, D}

Edges:
- Internal (expensive): A-B (100), C-D (100)
- Crossing (cheap): A-C (1), B-D (1), A-D (1), B-C (1)
```

**Algorithm Execution:**

**Step 1: Partition into {A,B} and {C,D}**
```
    A -------- C
    |100      |1
    |          |
    |100      |100
    |          |
    B -------- D
    |1        |1
    |          |
    +----------+

Left partition: {A,B}
Right partition: {C,D}
```

**Step 2: Solve recursively**
```
Left MST {A,B}: Must take edge A-B with weight 100
Right MST {C,D}: Must take edge C-D with weight 100

A --100-- B      C --100-- D
```

**Step 3: Connect with cheapest crossing edge**
```
Cheapest crossing edges all have weight 1
Pick A-C with weight 1

Final result:
A --100-- B
|        |
|1       |
|        |
+--1-----+--100-- D
          |
          C

Total cost = 100 + 100 + 1 = 201
```

**Actual OPTIMAL MST:**
```
A -------- C
|1        |1
|         |
|1        |1
+---------+
          D

Total cost = 1 + 1 + 1 + 1 = 4

B is connected via A-B-D path
```

**Why It Failed:**
- Algorithm was forced to build expensive local roads (A-B, C-D) before seeing cheaper highway system
- Made "local optimal" decisions without "global context"
- Divide-and-conquer doesn't work for MST because decisions in one partition affect the other

**LeetCode Pattern:**
*   **Lesson:** **Global vs. Local Optima.**
*   Many Dynamic Programming problems (like "House Robber") teach you that making a decision now (robbing this house) might prevent a better decision later. This Divide-and-Conquer approach failed because it made "final" decisions on the sub-problems without knowing the global context.
