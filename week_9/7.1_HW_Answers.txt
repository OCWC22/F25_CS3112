Homework Solutions: Section 7.1 - PARTITION Operation
======================================================

QUICKSORT BASICS - WHAT YOU NEED TO KNOW:
- Divide-and-conquer sorting algorithm
- Average case: O(n lg n), Worst case: O(n²)
- Sorts in place with O(lg n) stack space
- Key operation: PARTITION
- Strategy: Pick pivot, partition around it, recurse on both sides

PARTITION - THE HEART OF QUICKSORT:
- Purpose: Rearrange array so all elements ≤ pivot are on left, all > pivot are on right
- Returns: Final position of pivot
- Time: Θ(n) - linear in subarray size
- Key idea: Maintain invariant with two regions

PSEUDOCODE:
PARTITION(A, p, r):
    pivot = A[r]           // Last element as pivot
    i = p - 1              // Index of last element ≤ pivot
    for j = p to r - 1:
        if A[j] ≤ pivot:
            i = i + 1
            swap A[i] with A[j]
    swap A[i + 1] with A[r]
    return i + 1

QUICKSORT(A, p, r):
    if p < r:
        q = PARTITION(A, p, r)
        QUICKSORT(A, p, q - 1)
        QUICKSORT(A, q + 1, r)

INVARIANT DURING PARTITION:
At the start of each iteration of the for loop:
1. All elements in A[p..i] are ≤ pivot
2. All elements in A[i+1..j-1] are > pivot
3. A[r] = pivot

7.1-3: Give a brief argument that PARTITION runs in Θ(n) time

QUESTION RESTATED:
Prove that PARTITION on a subarray of size n takes linear time.

CONCEPT:
Analyze the number of operations in PARTITION.

STEP-BY-STEP PROOF:

1) INITIALIZATION:
   - pivot = A[r]: O(1)
   - i = p - 1: O(1)
   - Total: O(1)

2) FOR LOOP:
   - Runs from j = p to r - 1
   - Number of iterations: (r - 1) - p + 1 = r - p = n - 1
   - Each iteration:
     * Comparison: A[j] ≤ pivot - O(1)
     * Possibly increment i - O(1)
     * Possibly swap - O(1)
     * Total per iteration: O(1)
   - Total for loop: (n - 1) × O(1) = O(n)

3) FINAL SWAP:
   - swap A[i + 1] with A[r]: O(1)

4) TOTAL TIME:
   - O(1) + O(n) + O(1) = O(n)

5) LOWER BOUND:
   - Must examine each element at least once
   - Therefore Ω(n)

6) CONCLUSION:
   - Upper bound: O(n)
   - Lower bound: Ω(n)
   - Therefore: Θ(n)

ANSWER:
PARTITION runs in Θ(n) time because:
1. It performs exactly n-1 comparisons (one for each element except pivot)
2. Each comparison does O(1) work (compare, possibly swap)
3. Total: (n-1) × O(1) = Θ(n)

The algorithm must examine every element to determine which side of the pivot it belongs to, giving a lower bound of Ω(n). The for loop executes exactly n-1 times with constant work per iteration, giving an upper bound of O(n). Therefore, the running time is Θ(n).

FORMAL ANALYSIS:
Let n = r - p + 1 (size of subarray)
- Comparisons: exactly n - 1
- Swaps: at most n - 1
- Other operations: constant
- T(n) = c₁(n-1) + c₂ = Θ(n)

**CEO ANALOGY (No Background Needed):**
Why is PARTITION linear time? Because you look at each person exactly once!

- Walk through the line of employees once
- For each person: compare salary to benchmark, move if needed
- One pass = O(n) time
- Can't be faster (must check everyone)
- Can't be slower (only check once)

**Real-World Application**: In network packet routing, PARTITION-like algorithms split packets into priority queues in O(n) time. Every packet checked once, routed immediately.

**LeetCode Connection**: Understanding O(n) vs O(n log n) is crucial! PARTITION is O(n), full QUICKSORT is O(n log n). Know the difference!

7.1-4: Modify QUICKSORT to sort into monotonically decreasing order

QUESTION RESTATED:
Change QUICKSORT to sort from largest to smallest instead of smallest to largest.

CONCEPT:
Two approaches:
1. Modify PARTITION to put larger elements on left
2. Keep PARTITION same, reverse the final result

APPROACH 1: Modify PARTITION (Better)

Change the comparison in PARTITION from ≤ to ≥:

PARTITION-DECREASING(A, p, r):
    pivot = A[r]
    i = p - 1
    for j = p to r - 1:
        if A[j] ≥ pivot:    // Changed from ≤ to ≥
            i = i + 1
            swap A[i] with A[j]
    swap A[i + 1] with A[r]
    return i + 1

QUICKSORT-DECREASING(A, p, r):
    if p < r:
        q = PARTITION-DECREASING(A, p, r)
        QUICKSORT-DECREASING(A, p, q - 1)
        QUICKSORT-DECREASING(A, q + 1, r)

EXAMPLE:
Array: [5, 2, 8, 3, 9, 1]
pivot = 1

Using ≥ comparison:
- 5 ≥ 1? YES → swap to left partition
- 2 ≥ 1? YES → swap to left partition
- 8 ≥ 1? YES → swap to left partition
- 3 ≥ 1? YES → swap to left partition
- 9 ≥ 1? YES → swap to left partition

Result: [5, 2, 8, 3, 9, 1] → all elements ≥ 1 on left
After final swap: [5, 2, 8, 3, 1, 9]

Recursively sort left and right, final result: [9, 8, 5, 3, 2, 1]

APPROACH 2: Reverse at the end (Simpler but less efficient)

QUICKSORT-DECREASING(A, p, r):
    QUICKSORT(A, p, r)  // Sort in increasing order
    REVERSE(A, p, r)    // Reverse the array

REVERSE(A, p, r):
    while p < r:
        swap A[p] with A[r]
        p = p + 1
        r = r - 1

APPROACH 3: Use MIN-PARTITION (Alternative)

Instead of using the last element as pivot and putting smaller elements left:
- Use last element as pivot
- Put LARGER elements on left

ANSWER:
To sort in decreasing order, modify PARTITION to use ≥ instead of ≤:

PARTITION-DECREASING(A, p, r):
    pivot = A[r]
    i = p - 1
    for j = p to r - 1:
        if A[j] ≥ pivot:    // Key change: ≥ instead of ≤
            i = i + 1
            swap A[i] with A[j]
    swap A[i + 1] with A[r]
    return i + 1

This ensures that elements ≥ pivot are placed to the left, and elements < pivot are placed to the right, resulting in decreasing order after recursion.

COMPARISON OF APPROACHES:
1. Modify PARTITION: O(n lg n), sorts directly in decreasing order
2. Reverse after sorting: O(n lg n) + O(n) = O(n lg n), but extra pass
3. Both correct, approach 1 is more elegant

**CEO ANALOGY (No Background Needed):**
Sorting in reverse order? Just flip the comparison!

- Normal: Put smaller on left (≤ comparison)
- Reverse: Put larger on left (≥ comparison)
- Same algorithm, opposite direction
- Like organizing by highest-paid instead of lowest-paid

**Real-World Application**: In leaderboards (gaming, sports), you want highest scores first. Use reverse quicksort! Amazon product reviews sort by "most helpful" (descending).

**LeetCode Connection**: Many problems ask for "top K" or "largest K" - understanding descending sort helps optimize these!

KEY TAKEAWAYS FOR MIDTERM:

1. PARTITION ALGORITHM:
   - Choose pivot (usually last element)
   - Maintain two regions: ≤ pivot and > pivot
   - Scan array once, swapping elements to correct region
   - Place pivot in final position
   - Return pivot index

2. PARTITION INVARIANT:
   At each iteration:
   - A[p..i] contains elements ≤ pivot
   - A[i+1..j-1] contains elements > pivot
   - A[r] is the pivot
   - A[j..r-1] are unprocessed

3. TIME COMPLEXITY:
   - PARTITION: Θ(n) - examines each element once
   - QUICKSORT average: O(n lg n)
   - QUICKSORT worst: O(n²)

4. HOW PARTITION WORKS:
   - i tracks boundary between ≤ and > regions
   - j scans through array
   - When A[j] ≤ pivot: increment i, swap A[i] with A[j]
   - When A[j] > pivot: just move j forward
   - Finally: swap pivot into position i+1

5. PARTITION PROPERTIES:
   - In-place: O(1) extra space
   - Linear time: Θ(n)
   - Not stable: relative order may change
   - Deterministic: same input → same output

6. QUICKSORT STRUCTURE:
   - Divide: PARTITION into ≤ pivot and > pivot
   - Conquer: Recursively sort both partitions
   - Combine: Nothing (already in place)

7. MODIFYING FOR DECREASING ORDER:
   - Change ≤ to ≥ in PARTITION
   - Or reverse array after sorting
   - Both O(n lg n)

8. WHY Θ(n) NOT O(n)?:
   - Must examine every element (lower bound)
   - Examines each element exactly once (upper bound)
   - Therefore tight bound: Θ(n)

9. PARTITION VARIATIONS:
   - Lomuto partition: Uses last element as pivot (shown here)
   - Hoare partition: Uses two pointers from both ends
   - 3-way partition: Handles duplicate keys better

10. COMMON MISTAKES:
    - Forgetting to swap pivot at end
    - Off-by-one errors with i and j
    - Not maintaining invariant
    - Forgetting base case (p < r)

11. VISUALIZATION:
    [≤ pivot | > pivot | unprocessed | pivot]
     p...i    i+1..j-1   j...r-1      r
     
    After partition:
    [≤ pivot | pivot | > pivot]
     p...q-1    q      q+1...r

12. WHEN PARTITION FINISHES:
    - All elements in A[p..q-1] ≤ A[q]
    - A[q] is in its final sorted position
    - All elements in A[q+1..r] > A[q]
    - Ready to recurse on both sides
