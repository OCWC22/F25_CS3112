Exercise 3.1-1: Modify the lower-bound argument for insertion sort to handle input sizes that are not necessarily a multiple of 3
============================================================================================================

Original argument from textbook:
- Divides array of size n (multiple of 3) into three regions of n/3 elements each
- Places n/3 largest values in first n/3 positions
- Shows these must pass through middle n/3 positions to reach final n/3 positions
- Gives Ω(n²/9) = Ω(n²) lower bound

Modified argument for arbitrary n:
-----------------------------------

Let n be any positive integer. We can write n = 3k + r where k = ⌊n/3⌋ and r ∈ {0, 1, 2}.

Step 1: Divide the array into three regions
- First region: positions 1 to k (size k)
- Middle region: positions k+1 to 2k (size k)
- Last region: positions 2k+1 to n (size k + r)

Step 2: Worst-case input construction
Place the k largest values in the first k positions. In the sorted array, these k values must end up in the last k + r positions (positions 2k+1 to n).

Step 3: Movement analysis
Each of the k largest values must:
- Start in positions 1 to k
- Pass through all k middle positions (k+1 to 2k)
- End up in positions 2k+1 to n

Each value moves through at least k positions, requiring at least k executions of line 6.

Step 4: Lower bound calculation
- Number of values that must move: k = ⌊n/3⌋
- Distance each must move: at least k = ⌊n/3⌋ positions
- Total work: at least k × k = ⌊n/3⌋²

Since ⌊n/3⌋ ≥ (n-2)/3, we have:
⌊n/3⌋² ≥ ((n-2)/3)² = (n²-4n+4)/9

For n ≥ 4, this gives us (n²-4n+4)/9 ≥ n²/10, establishing an Ω(n²) lower bound.

Therefore, insertion sort has worst-case running time Ω(n²) for all input sizes n.


Exercise 3.1-2: Using reasoning similar to what we used for insertion sort, analyze the running time of the selection sort algorithm from Exercise 2.2-2
============================================================================================================

Selection Sort Algorithm (from Exercise 2.2-2):
```
SELECTION-SORT(A, n)
  for i = 1 to n - 1
    min_idx = i
    for j = i + 1 to n
      if A[j] < A[min_idx]
        min_idx = j
    if min_idx != i
      swap A[i] and A[min_idx]
```

Upper Bound Analysis - O(n²):
------------------------------
The outer loop runs n-1 times (i = 1 to n-1).
For each iteration i, the inner loop runs from j = i+1 to n, making n-i iterations.

Total comparisons:
∑(i=1 to n-1)(n-i) = (n-1) + (n-2) + ... + 1 = n(n-1)/2

Each comparison takes constant time, and at most one swap per iteration of the outer loop.
Therefore, the total time is at most cn² for some constant c, giving us O(n²).

Lower Bound Analysis - Ω(n²):
------------------------------
Key observation: Selection sort ALWAYS makes the same number of comparisons regardless of input!

Unlike insertion sort (where the inner loop can terminate early), selection sort's inner loop always completes all n-i iterations to find the minimum element in A[i:n].

For ANY input (even if already sorted):
- The algorithm makes exactly n(n-1)/2 comparisons
- This is true for best case, worst case, and average case

Since we always perform n(n-1)/2 = Θ(n²) comparisons, the lower bound is Ω(n²).

Tight Bound - Θ(n²):
--------------------
Since selection sort is both O(n²) and Ω(n²) for ALL inputs, we conclude:
- Best-case running time: Θ(n²)
- Worst-case running time: Θ(n²)
- Average-case running time: Θ(n²)

This makes selection sort less adaptive than insertion sort, which achieves Θ(n) in the best case.


Exercise 3.1-3: Generalize the lower-bound argument for insertion sort with αn largest values in first αn positions
============================================================================================================

Problem Setup:
Let α be a fraction where 0 < α < 1. Consider an input where the αn largest values start in the first αn positions.

Step 1: Array division
- First region: positions 1 to αn (contains the αn largest values)
- Middle region: positions αn+1 to (1-α)n
- Last region: positions (1-α)n+1 to n

Corrected Array Division:
------------------------
For the argument to work like the original (with three equal regions), we need:
- First region: positions 1 to αn
- Middle region: positions αn+1 to 2αn
- Last region: positions 2αn+1 to n

This requires 2αn ≤ n, which means α ≤ 1/2.

Additional Restriction: α ≤ 1/2
--------------------------------

Step 2: Movement Analysis
With α ≤ 1/2, we can partition the array into:
- First αn positions (containing the αn largest values)
- Next αn positions (the middle region)
- Final (1-2α)n positions (where the large values must end up)

Each of the αn largest values must:
- Pass through all αn middle positions
- End up in the last (1-2α)n positions

Step 3: Lower Bound Calculation
- Number of values moving: αn
- Distance each must move: at least αn positions
- Total work: at least (αn)² = α²n²

This gives us Ω(α²n²) = Ω(n²) since α is a positive constant.

Step 4: Optimal value of α
To maximize α²n² subject to α ≤ 1/2:

The function f(α) = α² is increasing for positive α, so we want the largest possible α.
Given the constraint α ≤ 1/2, the optimal value is α = 1/2.

When α = 1/2:
- We have n/2 largest values in first n/2 positions
- They must pass through positions n/2+1 to n
- This gives (n/2)² = n²/4 required operations

However, the original problem asked about middle (1-2α)n positions. To maximize α(1-2α):
Taking derivative: d/dα[α(1-2α)] = 1-4α = 0
This gives α = 1/4

When α = 1/4:
- n/4 values must pass through (1-2(1/4))n = n/2 middle positions
- Total work: (n/4)(n/2) = n²/8

Answer Summary:
- Additional restriction needed: α ≤ 1/2
- The value α = 1/3 from the original argument maximizes the lower bound when we want three equal regions
- For the general case with (1-2α)n middle positions, α = 1/4 maximizes the bound
