Exercise 2.1-2 — SUM-ARRAY: loop invariant and correctness proof
Question (CLRS 2.1-2)
- State a loop invariant for SUM-ARRAY and prove that the algorithm returns the sum of A[1..n].
- Provide running-time and space bounds and include a concrete worked example.

Step 0 — Notation and assumptions
- Arrays use 1-based indexing (A[1], A[2], …, A[n]) exactly as in the textbook.
- n ≥ 0; if n = 0 the loop body never executes.
- Array contents do not change during execution, and each addition/comparison has unit cost (RAM model).
- Summations treat the empty sum (no terms) as 0.

Step 1 — Restate the algorithm
  SUM-ARRAY(A, n)
    sum = 0
    for i = 1 to n
      sum = sum + A[i]
    return sum
- Thought process: copying the pseudocode verbatim anchors every later argument to a specific line.

Step 2 — Candidate loop invariant
Invariant sentence (to be proven): Immediately before iteration i begins, the variable sum stores the partial sum A[1] + A[2] + … + A[i-1].
- Why this choice? The loop has processed exactly the first i-1 elements when iteration i starts; the invariant must describe that “already processed” region.
- Hidden assumptions: array indexing is deterministic; the loop variable i increases sequentially (no skips, no resets).

Step 3 — Prove the loop invariant
Strategy: follow the textbook triad (Initialization, Maintenance, Termination).
- Initialization (i = 1): sum was set to 0. The prefix A[1..0] is the empty sum, also 0. Therefore the invariant holds before the first iteration.
- Maintenance (generic iteration): assume the invariant is true when iteration i begins (sum = A[1] + … + A[i-1]). The body updates sum ← sum + A[i], producing sum = A[1] + … + A[i]. As the loop increments i to i+1, the invariant sentence becomes “sum equals A[1] + … + A[(i+1)-1],” matching the new value. This uses the facts that increments are by 1 and the array is not modified elsewhere.
- Termination: the loop stops after i increments from n to n+1. Substitute i = n+1 into the invariant to obtain sum = A[1] + … + A[n], which is the desired total. The return statement therefore delivers the full sum.

Step 4 — Running time and space analysis
Perform an explicit count of work:
1. Initialization: one assignment sum = 0 (O(1)).
2. Loop iterations: i takes values 1, 2, …, n (n iterations).
   - Each iteration executes one addition and one assignment (sum = sum + A[i]).
   - Loop control performs a comparison (i ≤ n) and an increment (i ← i + 1).
3. Total primitive operations: Θ(n).
4. Space usage: the algorithm stores only sum and i in addition to the input array ⇒ Θ(1) auxiliary space.

Step 5 — Worked example (A = [7, 4, 9], n = 3)
The following table shows that the invariant’s claim matches the actual values on every iteration.
┌─────────┬───────────────────────────────┬─────────┬─────────────────────┬────────┬──────┐
│ i start │ Invariant claim               │ sum pre │ Body action         │ sum post │ i next │
├─────────┼───────────────────────────────┼─────────┼─────────────────────┼────────┼──────┤
│ 1       │ sum = A[1..0] = 0            │ 0       │ add A[1] = 7        │ 7      │ 2    │
│ 2       │ sum = A[1..1] = 7            │ 7       │ add A[2] = 4        │ 11     │ 3    │
│ 3       │ sum = A[1..2] = 7 + 4 = 11   │ 11      │ add A[3] = 9        │ 20     │ 4    │
└─────────┴───────────────────────────────┴─────────┴─────────────────────┴────────┴──────┘
Termination check: i next = 4 = n + 1, so the invariant yields sum = A[1..3] = 20, which matches the returned value.

Step 6 — Quick checkpoint
- Invariant statement proved for all iterations.
- Returned value equals Σ_{k=1}^n A[k].
- Running time Θ(n), space Θ(1).


Exercise 2.1-3 — INSERTION-SORT in decreasing order
Question (CLRS 2.1-3)
- Modify INSERTION-SORT to produce a nonincreasing (decreasing) order.
- State and prove a loop invariant; give running-time characteristics and a trace.

Step 0 — Notation and assumptions
- Same indexing, cost, and array stability assumptions as Exercise 2.1-2.
- Needed property: comparisons define a total order; swapping equal keys must preserve stability (no change to relative order for equal elements).

Step 1 — Modified algorithm
  INSERTION-SORT-DECREASING(A, n)
    for i = 2 to n
      key = A[i]
      j = i - 1
      while j > 0 and A[j] < key    // note the direction change
        A[j + 1] = A[j]
        j = j - 1
      A[j + 1] = key
- Only the comparison changes from “>” (increasing sort) to “<”. The remainder of the control structure is unchanged.

Step 2 — Loop invariant
Invariant sentence: Immediately before iteration i starts, the prefix A[1..i-1] contains the i-1 largest elements of the original array in nonincreasing order.
- Thought process: reuse the classic insertion-sort invariant but reinterpret “already sorted” as “sorted in decreasing order.”
- Assumptions: the while loop only moves items to the right when they are strictly smaller than the key, so larger items remain untouched and maintain order.

Step 3 — Proof of invariant
- Initialization (i = 2): the prefix A[1..1] contains only A[1], which is trivially in decreasing order and the largest element seen so far.
- Maintenance: assume the invariant holds at the start of iteration i. The while loop shifts every element less than key one position to the right, preserving the decreasing sequence among the shifted items. When the loop stops, j indicates the insertion point; storing key at A[j+1] inserts it adjacent to the first element that is ≥ key. The new prefix A[1..i] therefore remains in nonincreasing order.
- Termination: when the for loop exits, i = n + 1. Substituting into the invariant gives “A[1..n] is sorted in nonincreasing order,” exactly the desired postcondition.

Step 4 — Running time and space
- Worst/average cases: Θ(n²) comparisons and shifts. On iteration i, at most i-1 elements are shifted in the while loop; summing Σ_{i=2}^n (i-1) = n(n-1)/2 gives Θ(n²).
- Best case: Θ(n) when the array is already sorted in decreasing order (the while condition fails immediately each time).
- Space: Θ(1) auxiliary space (only key and j in addition to the input array).
- Stability: The strict comparison (<) prevents equal keys from moving past one another, keeping the algorithm stable.

Step 5 — Detailed trace (A = [3, 1, 4, 2])
┌────────────┬────────────┬─────────┬─────────────────────────────┬────────────┐
│ Iteration  │ key        │ j start │ while-loop actions          │ Array      │
├────────────┼────────────┼─────────┼─────────────────────────────┼────────────┤
│ i = 2      │ key = 1    │ 1       │ A[1] = 3 < 1? no (shift 0)  │ [3, 1, 4,2]│
│ i = 3      │ key = 4    │ 2       │ shift A[2]=1 → A[3], j=1    │ [3, 1, 1,2]│
│            │            │         │ shift A[1]=3 → A[2], j=0    │ [3, 3, 1,2]│
│            │            │         │ place key at A[1]           │ [4, 3, 1,2]│
│ i = 4      │ key = 2    │ 3       │ shift A[3]=1 → A[4], j=2    │ [4, 3, 1,1]│
│            │            │         │ A[2]=3 < 2? no              │            │
│            │            │         │ place key at A[3]           │ [4, 3, 2,1]│
└────────────┴────────────┴─────────┴─────────────────────────────┴────────────┘
After the loop (i = 5), the invariant asserts that A[1..4] is sorted in decreasing order, matching the final array [4, 3, 2, 1].

Step 6 — Quick checkpoint
- Invariant holds; loop terminates with A sorted in decreasing order.
- Time Θ(n²) worst/avg, Θ(n) best; space Θ(1).


Exercise 2.1-4 — LINEAR-SEARCH: invariant and correctness
Question (CLRS 2.1-4)
- Provide a loop invariant for LINEAR-SEARCH and prove the algorithm returns the index of x or NIL when x is absent.
- Present running times for best, average, and worst cases and show a trace.

Step 0 — Notation and assumptions
- Same array model and cost assumptions as before.
- Additional probabilistic assumption for the average-case analysis: when x is present, it is equally likely to appear in any position 1..n.

Step 1 — Algorithm recap
  LINEAR-SEARCH(A, n, x)
    for i = 1 to n
      if A[i] == x
        return i
    return NIL
- Thought process: state the direct “scan left-to-right” procedure before manipulating invariants.

Step 2 — Loop invariant
Invariant sentence: Immediately before iteration i, x is not equal to any element in the prefix A[1..i-1].
- Concept: the loop progressively rules out positions to the left of i.
- Assumptions: comparisons are exact and do not modify the array.

Step 3 — Loop invariant proof
- Initialization (i = 1): the prefix A[1..0] is empty, so x trivially does not appear there.
- Maintenance: suppose the invariant holds before iteration i. If A[i] == x, the algorithm returns i, satisfying the specification. Otherwise x is absent from A[1..i], so the invariant is ready for iteration i+1.
- Termination: if the loop finishes without returning, i = n + 1. Substitute this into the invariant to conclude x is not in A[1..n]; returning NIL is therefore correct.

Step 4 — Running time analysis
- Best case Θ(1): x found at position 1.
- Worst case Θ(n): x at position n or absent; the loop inspects all n elements.
- Average case Θ(n): with a uniform distribution over positions, see Step 5.
- Space: Θ(1) auxiliary (only i).

Step 5 — Average-case expectation (uniform model)
1. Define the random variable C = number of inspections until success. If x is at position k, then C = k.
2. The uniform model gives P[C = k] = 1/n for k = 1,…,n.
3. Compute the expectation explicitly:
     E[C] = Σ_{k=1}^n k · P[C = k]
          = Σ_{k=1}^n k · (1/n)
          = (1/n) · (1 + 2 + … + n)
          = (1/n) · n(n + 1)/2
          = (n + 1)/2.
4. Interpretation: on average we inspect (n + 1)/2 elements, so the average running time grows linearly with n (Θ(n)).

Step 6 — Trace examples (A = [9, 4, 7, 2, 5])
Case 1: target present at i = 1 (best case) ⇒ return 1 after one comparison.
Case 2: target present at i = 3 ⇒ comparisons at i = 1, 2, 3 → return 3.
Case 3: target absent ⇒ comparisons at all i = 1..5 → return NIL.
These traces match the invariant and expectation analysis above.

Step 7 — Quick checkpoint
- Loop invariant validated; correctness follows from termination case.
- Time: Θ(1) best, Θ(n) average, Θ(n) worst; space Θ(1).
