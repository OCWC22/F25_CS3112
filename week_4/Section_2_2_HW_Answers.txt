Exercise 2.2‑2 — Selection sort: pseudocode, invariant, passes, running time
Question (textbook 2.2‑2)
- Give pseudocode for SELECTION-SORT on A[1..n], state a loop invariant, explain why the outer loop runs only n−1 times, and analyze both best- and worst-case running times.

Solution (step-by-step)
Step 1 — Write the algorithm explicitly (1‑based)
  SELECTION-SORT(A, n)
    for i = 1 to n − 1
      min_idx = i
      for j = i + 1 to n
        if A[j] < A[min_idx]
          min_idx = j
      if min_idx ≠ i
        swap A[i] and A[min_idx]
  • Outer loop marks the boundary between the sorted prefix A[1..i−1] and unsorted suffix A[i..n].
  • Thought process: rewrite the reference pseudocode so later reasoning points to concrete lines (outer vs inner loop).
  • Assumptions: indices are valid for 1 ≤ i ≤ n, comparisons are total order comparisons, and swap executes atomically.

Step 2 — Declare the loop invariant
  Invariant sentence: At the start of iteration i, the prefix A[1..i−1] stores the i−1 smallest elements of the array in nondecreasing order and every element in that prefix is ≤ every element in A[i..n].
  • Concept focus: express what we know about the sorted prefix and how it relates to the remainder; this is the key claim we will maintain.
  • Assumption: the comparison used in the inner loop truly returns the smaller element according to the desired ordering.

Step 3 — Prove the invariant
  • Strategy: check initialization, maintenance, and termination exactly as in the textbook proof, but with the explicit invariant stated above.
  (a) Initialization: For i = 1 the prefix A[1..0] is empty, so it is trivially sorted and the claim holds.
  (b) Maintenance: During iteration i the inner loop finds the index of the minimum element in A[i..n]. Swapping it with A[i] appends the next-smallest element to the sorted prefix, so A[1..i] satisfies the invariant for the next iteration. The reasoning assumes the swap leaves all other entries unchanged.
  (c) Termination: When the loop ends, i = n. Plugging that into the invariant says A[1..n−1] is sorted and contains the n−1 smallest elements. The last remaining element A[n] must therefore be the largest, so the whole array is sorted.

Step 4 — Justify the “n−1 passes” statement
  • Once positions 1 through n−1 hold the correct elements, the remaining element automatically belongs at index n. An additional pass would perform no work; this depends on the assumption that the array is finite and the algorithm never introduces duplicates.

Step 5 — Analyze running time carefully
  • Comparisons: Pass i performs (n−i) comparisons. Summing gives Σ_{i=1}^{n−1} (n−i) = n(n−1)/2 = Θ(n^2).
  • Swaps: At most one swap per pass (≤ n−1) ⇒ Θ(n).
  • Best case: Still Θ(n^2) comparisons because every pass inspects the unsorted suffix even if the array is sorted.
  • Worst case: Θ(n^2) for the same reason; swaps do not change the dominant term.
  • Space: Θ(1) extra variables (min_idx, i, j).
  • Modeling note: assumes each comparison/swap costs O(1) and array reads/writes dominate runtime.

Step 6 — Show the algebra for comparison counts
  1. Start with the series Σ_{i=1}^{n−1} (n−i). Distribute to obtain (n−1) + (n−2) + … + 1.
  2. Pair terms from opposite ends: (1+(n−1)) + (2+(n−2)) + … Each pair sums to n and there are (n−1)/2 pairs when n−1 is odd, or (n−1)/2 pairs plus a middle term when even.
  3. Therefore the total comparisons equal n(n−1)/2, which is Θ(n^2). This explicit derivation confirms the intuition that the outer loop performs a “triangle number” of comparisons.
  4. Cross-check with the compact example table: the column “j-range scanned” lists the same lengths (5,4,3,2,1 when n=6), whose sum is 15 = 6·5/2.

Exercise 2.2‑3 — Linear search average vs worst case
Question (textbook 2.2‑3)
- Suppose x is present in A[1..n] and is equally likely to appear in any position. How many elements does LINEAR-SEARCH inspect on average, and how does that compare to the worst case? State the answers in Θ-notation and show the arithmetic.

Solution (step-by-step)
Step 1 — Translate the probability model
  • Let the random variable C be the number of inspections performed.
  • Because x is equally likely to be at any index k (1 ≤ k ≤ n), P[C = k] = 1/n.
  • Assumption: conditional on x being present, positions are uniformly distributed; this is the only randomness we use.

Step 2 — Compute the expectation explicitly
  1. Write the random variable explicitly: C = k when x appears first at index k.
  2. Use the uniform model: P[C = k] = 1/n for every k ∈ {1,…,n}.
  3. Substitute into the expectation formula:
       E[C] = Σ_{k=1}^n k · P[C = k] = Σ_{k=1}^n k · (1/n).
     Factor out 1/n and expand the sum of the first n integers:
       E[C] = (1/n) · (1 + 2 + … + n).
  4. Apply the closed form 1 + 2 + … + n = n(n+1)/2, giving E[C] = (1/n) · n(n+1)/2 = (n+1)/2.
  5. Interpretation: the average number of inspections grows linearly with n, so the average-case running time is Θ(n).
  • Thought process: translate the narrative “each position equally likely” into a simple arithmetic mean; recognize the triangular-number formula.

Step 3 — Identify the worst case
  • The loop does the most work when x sits at position n or is absent.
  • In both situations, C = n inspections ⇒ Θ(n) worst-case time.
  • Assumption: cost per comparison is constant, so the number of inspected items directly reflects running time.

- Example 2 (present in the middle)

  1   9      != 7        continue

- Example 3 (absent)
  i  A[i]  compare to x  action/result
  1   9      != 8        continue
  2   4      != 8        continue
  3   7      != 8        continue
  4   2      != 8        continue
  5   5      != 8        continue
  —   —        —         return NIL (not found)

Average‑case calculation (assume x is present and equally likely at any position)
- Let C be the number of checks. If x is at position k, then C = k.
- Probability x is at position k is 1/n, for k ∈ {1,…,n}.
- Expected checks: E[C] = Σ_{k=1}^n (k · 1/n) = (1/n) · (1+2+…+n) = (1/n) · n(n+1)/2 = (n+1)/2.
- Therefore average‑case running time is Θ(n) (linear in n).

Worst case
- If x is absent (or at the last position), the loop examines all n elements: C = n.
- Worst‑case running time is Θ(n).

0‑based indexing mapping
- for i = 0..n−1; test A[i] and return i when found; NIL if loop completes.
- Average checks become (n+1)/2 in 1‑based; in 0‑based you can think of positions 0..n−1 with expected checks (n+1)/2 as well, measured in element inspections.

Exercise 2.2‑4 — Forcing a good best case for any sort
Question (textbook 2.2‑4)
- How can any comparison sort be modified so that its best case becomes linear time without changing its other asymptotic bounds?

Solution (step-by-step)
Step 1 — Pick a linear-time “easy case” test
  • Define IS-SORTED(A, n): scan once and verify A[1] ≤ A[2] ≤ … ≤ A[n].
  • Cost: Θ(n) comparisons, Θ(1) space.
  • Thought process: identify a property (“already sorted”) that can be tested cheaply and guarantees the answer.

Step 2 — Wrap the original sorting algorithm
  IS-SORTED(A, n)
    for i = 2 to n
      if A[i] < A[i−1]
        return FALSE
    return TRUE

  WRAP-SORT(A, n)   // BASE-SORT is the given algorithm
    if IS-SORTED(A, n) == TRUE
      return A                 // already sorted ⇒ finish in Θ(n)
    else
      BASE-SORT(A, n)          // fall back to the original routine
      return A
  • Assumption: the check and base sort operate on the same data representation so we can reuse results.

Step 3 — Explain the complexity effect
  • Best case: If the array is already sorted, IS-SORTED returns TRUE and the wrapper finishes in Θ(n).
  • Otherwise: You pay Θ(n) for the check plus time(BASE-SORT). Because BASE-SORT is at least Ω(n), the Θ(n) precheck does not change its Θ-bound in average or worst cases.
  • Space overhead: Θ(1) beyond what BASE-SORT already uses.
  • Thought process: treat the wrapper as “check + original cost”; compare the additional Θ(n) work to the dominant cost of BASE-SORT.

Step 4 — Write the running-time equation explicitly
  T_wrapper(n) = T_check(n) + T_base(n) = Θ(n) + T_base(n).
  • Best case (already sorted): T_base(n) = 0 ⇒ T_wrapper(n) = Θ(n).
  • Worst/average case: T_base(n) dominates, so T_wrapper(n) ∈ Θ(T_base(n)).
  • Assumption: BASE-SORT’s cost is unaffected by the check (no side effects).

Notes
- Many practical implementations (e.g., bubble sort with a no-swap flag) apply this exact idea.

2.2‑4 Step‑by‑step walkthrough (learning + show‑your‑work)
Goal
- Purpose: convert the abstract wrapper idea into concrete traces that verify the reasoning.
Goal
- Modify any sorting algorithm so that its best case is “good” (linear time) by quickly detecting already‑sorted inputs and exiting early.

Wrapper pattern
  IS-SORTED(A, n)
    for i = 2 to n
      if A[i] < A[i−1]
        return FALSE
    return TRUE

  WRAP-SORT(A, n)   // BASE-SORT is your original sorting algorithm
    if IS-SORTED(A, n) == TRUE
      return A                 // best case: just one pass
    else
      BASE-SORT(A, n)          // fall back to the usual algorithm
      return A

Concrete example 1 (already sorted)
- Input A = [1, 2, 3, 4, 5]
- IS-SORTED scans pairs (2≥1, 3≥2, 4≥3, 5≥4): no violation → TRUE → WRAP-SORT returns immediately.
- Time: Θ(n) (one pass only). This achieves a “good best case.”

Compact check table (already sorted)
  i  compare A[i] vs A[i−1]  violation?  state
  2    2 ≥ 1                  no         keep scanning
  3    3 ≥ 2                  no         keep scanning
  4    4 ≥ 3                  no         keep scanning
  5    5 ≥ 4                  no         keep scanning
  —    —                      —          IS-SORTED = TRUE → return

Concrete example 2 (not sorted)
- Input A = [3, 1, 4, 2]
- IS-SORTED: at i=2, detect 1 < 3 → FALSE → run BASE-SORT (e.g., mergesort, quicksort, heapsort, insertion sort, etc.).
- Total time: Θ(n) for the precheck + time(BASE-SORT). Asymptotically the BASE-SORT term dominates, so worst‑case/average‑case complexity is unchanged.

Compact check table (not sorted)
  i  compare A[i] vs A[i−1]  violation?  state
  2    1 < 3                  yes         IS-SORTED = FALSE → run BASE-SORT

Why this does not “cheat” the analysis
- We truly improved only the best case: when the input is already sorted (or trivially “nice”), we can finish in Θ(n) by observation.
- On typical random inputs, the Θ(n) precheck is dwarfed by the Θ(n log n) or Θ(n^2) sorting work, so your overall Θ bounds remain the same for average/worst cases.

0‑based indexing mapping
- In IS-SORTED use i = 1..n−1 and compare A[i] < A[i−1] (0‑based). The wrapper logic is identical.
