### Technical Highlights:

**RAM Model Key Points:**
- Sequential execution (no parallelism)
- Constant-time primitive operations
- Constant-time array access
- Machine-independent analysis
- Good predictor of real performance

**Analysis Key Points:**
- Running time = function of input size
- Count each line's executions
- Sum: T(n) = Σ(cost × times)
- Simplify to asymptotic notation
- Focus on dominant term

**Selection Sort Key Points:**
- Always makes n(n-1)/2 comparisons
- Best case = worst case = Θ(n²)
- Cannot exit early (unlike insertion sort)
- Loop invariant: smallest elements in place
- Runs n-1 iterations (last element auto-correct)

**Case Analysis Key Points:**
- Best case: minimum time over all inputs
- Worst case: maximum time over all inputs
- Average case: expected time over random inputs
- Worst case most commonly analyzed
- Average often similar to worst asymptotically

### Problem-Specific Insights:

**2.2-1 (Simplify to Θ):**
- Function: n³/1000 + 100n² - 100n + 3
- Dominant term: n³/1000
- Drop constant: n³
- Answer: Θ(n³)
- Shows how to handle constants and multiple terms

**2.2-2 (Selection sort):**
- Find minimum, swap, repeat
- Loop invariant: A[1:i-1] has i-1 smallest elements
- Why n-1: Last element automatically correct
- Always Θ(n²): cannot exit early
- Worse than insertion sort for nearly-sorted data

**2.2-3 (Linear search cases):**
- Average: (n+1)/2 checks
- Worst: n checks
- Both Θ(n) (same asymptotic growth)
- Shows average ≈ worst asymptotically

**2.2-4 (Improve best case):**
- Technique: Check if sorted first
- Cost: Θ(n) preprocessing
- Best case becomes Θ(n)
- Worst case unchanged
- Works for any sorting algorithm
