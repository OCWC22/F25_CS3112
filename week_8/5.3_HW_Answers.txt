**FUNDAMENTALS PRIMER (Since You Said You Know Nothing)**

Before we dive into the problems, let's build from zero. Imagine you're new to all this—I'll explain like we're sitting in a classroom.

1. **What is Probability?**  
   Probability is a number between 0 and 1 that tells us how likely something is to happen. 0 means "impossible," 1 means "certain," and 0.5 means "50/50 chance." We use it to predict outcomes in uncertain situations, like flipping a coin. Why? Because the world isn't deterministic—randomness exists, and we need tools to handle it. How? We calculate it by dividing the number of favorable outcomes by the total possible outcomes. For example, in a fair coin flip, P(Heads) = 1/2 because there's 1 head out of 2 possibilities. Context: In algorithms (like the ones in these problems), we use probability to analyze how "random" inputs or choices affect performance.

2. **What is Expectation (Expected Value)?**  
   Expectation is the "average" outcome if you repeat an experiment many times. It's like asking, "If I do this a million times, what do I expect on average?" Why? It helps us understand long-term behavior even if individual outcomes vary. How? For a random variable X (something that can have different values, like the number of hires), E[X] = sum of (each possible value × its probability). Example: For a die, E[value] = (1+2+3+4+5+6)/6 = 3.5. Context: In these problems, we use it to find average costs or counts, which is key for algorithm analysis.

3. **What are Indicator Random Variables?**  
   An indicator is a simple 0-or-1 variable that "flags" whether something happens. It's like a light switch: 1 if "on" (event happens), 0 if "off." Why? They're easy to work with and help break down complex problems into yes/no questions. How? Define I_A = 1 if event A occurs, 0 otherwise. Then, E[I_A] = P(A) (that's a key lemma we'll use). Context: In hiring or dice problems, we use them to count things like "number of hires" by summing many indicators.

4. **Linearity of Expectation**  
   This says E[X + Y] = E[X] + E[Y], even if X and Y are dependent (related). Why? It simplifies calculations—you don't need to worry about dependencies. How? Just add up the individual expectations. Example: If X and Y are dice rolls, E[X+Y] = E[X] + E[Y] regardless of if they're linked. Context: Crucial here because events in these problems (like hires) are often dependent.

5. **Random Permutations and Orderings**  
   A permutation is a rearrangement of items. "Uniform random" means every possible order is equally likely (probability 1/n! for n items). Why? It models fairness, like shuffling cards. How? We assume all n! orders are possible and equally probable. Context: Used in hiring problems where candidates arrive in random order.

6. **Harmonic Numbers**  
   H_n = 1 + 1/2 + 1/3 + ... + 1/n. It's approximately ln(n) + 0.577 (Euler's constant). Why? It shows up in sums of 1/k. Context: In hiring problems, it gives the expected number of hires.

**SOLUTIONS**

**Solution to 5.3-1: Adjusting RANDOMLY-PERMUTE for nonempty prefix**

Step 0: Understand the issue.  
   - Original RANDOMLY-PERMUTE has a loop invariant for an empty subarray before the first iteration, which Professor Marceau says is invalid (probability 0 for 0-permutation in empty array).  
   - Why fix? To make the invariant apply to a nonempty prefix.  
   - How: Add a step before the loop to randomize a nonempty prefix.  
   - Context: This is about proving algorithm correctness with loop invariants.

Step 1: Rewrite the procedure.  
   - RANDOMLY-PERMUTE-PRIME(A, n):  
     1. swap A[1] with A[RANDOM(1, n)]  # Randomize first element.  
     2. for i = 2 to n  
        swap A[i] with A[RANDOM(i, n)]  # Rest as before.

Step 2: New loop invariant.  
   - Just before ith iteration (i >= 2), prefix A[1..i-1] contains each possible (i-1)-permutation with probability (n - i + 1)! / n!.  
   - Why? Now it's nonempty for i=2 (after step 1, A[1] is randomized).  
   - How: This matches the original but starts from nonempty.

Step 3: Prove the invariant.  
   - Initialization: After step 1, A[1] contains each 1-permutation with probability (n-1)! / n! (swapping makes any element equally likely in A[1]).  
   - Maintenance: Assume for i. In iteration i, choose random from A[i..n], swap with A[i]. Conditioned on prefix being uniform (i-1)-permutation, P(next is any) = 1/(n-i+1). Multiply probabilities: (n-i)! / n!.  
   - Termination: After i=n+1, whole array is uniform n-permutation with probability 1/n!.  
   - Why each part? Standard proof technique: show it holds at start, each step preserves it, and end gives correctness.  
   - Context: This addresses Marceau's objection while keeping the algorithm correct and O(n) time.

**Solution to 5.3-2: Does PERMUTE-WITHOUT-IDENTITY work?**

Step 0: Understand the goal.  
   - Produce any permutation except the identity (where A[i] stays at i). Uniformly over the n!-1 non-identity permutations.  
   - The procedure: For i=1 to n-1, swap A[i] with a random later position.  
   - Why analyze? To check if it's uniform and excludes identity.  
   - How: Simulate for small n and check distribution.  
   - Context: This is about randomized algorithms and uniformity.

Step 1: Analyze for n=3 (smallest case).  
   - A = [1,2,3].  
   - i=1: Swap A[1] with A[RANDOM(2,3)] — so A[1] becomes 2 or 3, each P=1/2.  
   - i=2: Swap A[2] with A[RANDOM(3,3)] — only A[3], so must swap A[2] and A[3].  
   - Possible outcomes: (2,3,1) or (3,1,2). Each P=1/2.  
   - Why? The swaps force specific changes.

Step 2: Identify failures.  
   - Identity [1,2,3] never occurs (good). But missing [1,3,2], [2,1,3], [3,2,1], [3,1,2] wait, (3,1,2) is there but others aren't. Only 2 out of 6 permutations.  
   - Not uniform over the 5 non-identity: It only produces 2 specific ones.  
   - Why biased? Each swap eliminates possibilities; later choices have too few options, not spreading probability evenly.  
   - How: For larger n, permutations where elements stay put early become impossible.

Step 3: Conclusion.  
   - No, it doesn't work as intended. Use rejection sampling (generate uniform permutation, retry if identity) for correctness.  
   - Context: Shows why careful design is needed for uniform distributions.
