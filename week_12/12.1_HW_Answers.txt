12.1-2 - BST property vs. Min-heap property; can a min-heap print sorted in O(n)?

BST property: for every node x, all keys in x.left ≤ x.key ≤ all in x.right (strict if all keys are distinct). This gives global in-order order.

Min-heap property: every parent ≤ each child. This does not impose in-order ordering between subtrees/siblings; it only guarantees the minimum at the root.

Sorted output in O(n) from a min-heap? No. You can repeatedly extract the min, but each extract-min costs O(log n), so printing in order is Θ(n log n), not Θ(n). You can't do it in linear time from a plain heap because the structure doesn't store global order. (A BST can in-order traverse in Θ(n).)

12.1-4 - Recursive preorder / postorder in Θ(n)

Preorder (root, left, right):

PREORDER(x):
  if x = NIL: return
  visit(x)
  PREORDER(x.left)
  PREORDER(x.right)

Postorder (left, right, root):

POSTORDER(x):
  if x = NIL: return
  POSTORDER(x.left)
  POSTORDER(x.right)
  visit(x)

Why Θ(n): each node is visited a constant number of times; total work sums to Θ(n) and stack depth is O(h) (≤ O(n), O(log n) on balanced trees).
